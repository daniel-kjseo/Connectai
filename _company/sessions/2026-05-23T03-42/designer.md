### 📂 [디자인 시스템 업데이트] Anomaly Detection Visual System v1.1
**(파일 경로: sessions/2026-05-23T01-17/designer_v1.1_anomaly_system.md)**

이 문서는 '소유권 격차 체험' 인터랙션의 모든 비정상(Non-Success) 상태에 적용되어, 사용자의 불안감을 증폭시키는 디자인 시스템 가이드입니다.

#### 1. 🔍 핵심 컴포넌트: Anomaly Indicator (Anomaly/오류 감지 표시기)
| 속성 | 스펙 상세 | 개발 참고 사항 |
| :--- | :--- | :--- |
| **목표** | 사용자에게 '무언가 중요한 것이 누락되거나 손상되었다'는 심리적 위협을 전달한다. 단순한 오류 코드는 사용하지 않는다. | **Tone:** 경고문(Warning), 공공 기록물의 훼손 느낌 |
| **시각 요소** | 배경에 낮은 주파수의 미세한 노이즈 필터 (Grain/Noise Overlay) 적용. 모든 정보의 모서리나 테두리에 불안정한 `Crimson-Red` 색상의 점선 경고 테두리를 배치한다. | CSS Filter: `url(#noise-filter)` 사용 권장. |
| **사운드 브리프** | 낮은 볼륨의, 불규칙적으로 깜빡이는 '삐-' 하는 비명음(Subtle Beep/Anomaly Tone)을 3초 간격으로 삽입한다. (강요하지 않는 불안감 유발) | 사운드 파일: `anomaly_beep.mp3` (반복 재생 로직 필요) |

#### 2. ⏳ 인터랙티브 상태별 스펙 상세 (Timing & Feedback)

##### A. Loading State: [🔍 Provenance Verification Process]
*   **목표:** '단순히 로딩 중'이 아님을 인지시킨다. 시스템이 *노력하고 있지만, 확신하지 못하는* 과정을 보여줘야 한다.
*   **UI 요소:** 일반적인 스피너 대신, `[STATUS: Verifying Provenance Link...]`와 같은 텍스트 로그가 불규칙한 속도로 타이핑되는 시뮬레이션(Typewriter Effect)을 사용한다.
*   **애니메이션 타이밍:**
    *   초기 로드 (0-1s): 화면이 갑자기 **잠시 흐릿해지고(Blur)**, 낮은 주파수의 진동 애니메이션(`translateY(-1px)`를 20ms 간격으로 반복)을 적용한다. (시스템 오류 같은 느낌)
    *   로그 진행 (1-3s): 로그 메시지가 출력될 때마다 **약간의 지연 시간(Staggered Delay)**이 발생하여, 시스템이 데이터를 찾는 데 어려움을 겪는 것처럼 보이게 한다.
    *   **Hover/Interaction:** 사용자가 로딩 영역을 마우스 오버할 경우, 로그 타이핑 속도가 순간적으로 느려지며, `[ERROR: Data Stream Interrupted]`라는 메시지가 플래시백 되도록 설계한다 (0.5초간).

##### B. Failure State: [🚨 Anomaly Detected / Provenance Gap]
*   **발생 조건:** 사용자의 이름 요소(Prefix/Suffix) 조합 중, 유효한 서사적 근거가 부족할 때.
*   **UI 요소:** 전체 영역에 노이즈 필터와 Crimson-Red 경고 테두리가 활성화된다. 중앙에 거대한 `[ALERT: UNVERIFIED ASSET]` 배너를 배치한다.
*   **애니메이션 타이밍:**
    *   **팝업 (0s):** 모든 것이 순간적으로 멈추고(Pause), 화면이 강렬한 Red Flash와 함께 진동 애니메이션을 겪는다.
    *   **메시지 등장 (0.5s):** `Anomaly Detected` 문구가 마치 기계가 녹음한 듯한, 약간 왜곡된 음성으로 재생되며 타이포그래피 효과와 함께 나타난다.
    *   **강조점:** "이 자산은 현재의 기록만으로는 **완전성이 입증되지 않았습니다.**"라는 핵심 카피는 굵게 표시되고, 글자가 마치 깨지는 듯한(Glitch Effect) 애니메이션을 적용한다.

##### C. Missing Data State: [❓ Fragmented Record]
*   **발생 조건:** 사용자가 이름에 대한 '원본 기록'이 필요함을 자극해야 하는 지점 (Paywall 직전).
*   **UI 요소:** 데이터가 누락된 부분을 마치 **찢겨진 종이나 깨진 디지털 화면 조각(Fragment)**처럼 시각화한다. 실제 정보는 블러 처리되거나, `[---MISSING DATA: RECONNECTION REQUIRED---]` 같은 플레이스홀더로 대체된다.
*   **애니메이션 타이밍:**
    *   정보가 로드되어야 할 영역에 접근할 때 (Hover), 해당 부분이 마치 **깨진 유리 파편이 재조립되는 듯한(Shattering/Reassembling)** 미세한 애니메이션을 보여준다.
    *   파편 사이의 빈 공간(Gap)은 어둡고 불안정한 느낌으로 처리하며, 이 Gap 위에만 유료 구매 버튼이 '빛'처럼 강조되어야 한다.

#### 3. ✨ 최종 결론 및 액션 플랜 (Actionable Summary)
위 스펙들은 모두 **'불안감 조성 → 해결책 제시(Paywall)'**라는 서사적 흐름을 따르도록 설계되었습니다. 개발팀은 이 상태 변화 로직에 가장 많은 리소스를 투입해야 하며, 특히 사운드와 애니메이션 타이밍이 사용자의 심리적 경험을 좌우할 것입니다.
